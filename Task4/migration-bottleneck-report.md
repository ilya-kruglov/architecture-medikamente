# Отчёт: Анализ узких мест при миграции

## 1. Введение

Компания «Медикаменте» планирует миграцию с текущей архитектуры (файловый монолит на Windows Server 2022 с Excel, 1С в файловом режиме и OLE-интеграциями) на современную микросервисную архитектуру с использованием Java, Kubernetes, PostgreSQL и ClickHouse.

Данный отчёт систематизирует потенциальные узкие места, которые могут негативно повлиять на производительность, стабильность и сроки миграции.

## 2. Диаграмма Исикавы (Рыбья кость)

Диаграмма построена по шести категориям, охватывающим все аспекты системы:

| Категория | Описание |
|-----------|----------|
| **Инфраструктура** | Физическое оборудование, сеть, хранилище |
| **Программное обеспечение** | Существующие приложения и их архитектурные ограничения |
| **Интеграция** | Способы взаимодействия между системами |
| **Данные** | Состояние, классификация и управление данными |
| **Персонал** | Квалификация, процессы, вовлечённость команды |
| **Процессы** | CI/CD, тестирование, управление изменениями |

Полная диаграмма доступна в файле:
- `ishikawa-diagram.drawio.xml` (draw.io)

## 3. Детальный анализ проблем по категориям

### 3.1. Инфраструктура

| Проблема | Описание | Влияние на миграцию |
|----------|----------|---------------------|
| **Физический сервер (Windows 2022)** | Единая точка отказа, нет горизонтального масштабирования | Невозможность развернуть микросервисы с отказоустойчивостью |
| **Сетевая инфраструктура** | Локальная сеть без сегментации, ограниченная пропускная способность | Узкое место при росте трафика между сервисами |
| **Хранилище (общий диск)** | I/O бутылочное горлышко, нет репликации, низкая производительность | Задержки при чтении/записи, проблемы с согласованностью |

### 3.2. Программное обеспечение

| Проблема | Описание | Влияние на миграцию |
|----------|----------|---------------------|
| **1С (файловый режим)** | Блокировки файлов при конкурентном доступе, отсутствие транзакционности | Сложность интеграции с новыми сервисами, риск потери данных |
| **Excel-файлы как БД** | Нет ACID, ручные ошибки, дублирование | Миграция данных потребует очистки и дедупликации |
| **Exchange Mail (устаревший)** | Нет шифрования, устаревшие протоколы | Проблемы с безопасностью при интеграции с новыми уведомлениями |

### 3.3. Интеграция

| Проблема | Описание | Влияние на миграцию |
|----------|----------|---------------------|
| **OLE-интеграция 1С ↔ ККМ** | Устаревшая технология, нет шифрования, синхронный вызов | Требуется полная переработка, риск простоев касс |
| **Ручной обмен с лабораторией** | Передача файлов по email, нет API | Невозможность автоматизировать процесс, задержки |
| **Нет API-шлюза** | Нет контроля доступа, rate limiting, маршрутизации | Новые сервисы останутся без единой точки входа |

### 3.4. Данные

| Проблема | Описание | Влияние на миграцию |
|----------|----------|---------------------|
| **ПДн/PII и Medical в открытом виде** | Нарушение 152-ФЗ, риск утечки | Требуется шифрование и маскирование до миграции |
| **Нет тегирования и классификации** | Невозможно применить ABAC, нет аудита | Риск несанкционированного доступа в новой системе |
| **Бессрочное хранение** | Нарушение сроков хранения, избыточный объём | Миграция большого объёма данных, сложность очистки |

### 3.5. Персонал

| Проблема | Описание | Влияние на миграцию |
|----------|----------|---------------------|
| **Нет опыта микросервисов** | Команда знает Java, но не Kubernetes, ClickHouse | Долгий ramp-up, риск архитектурных ошибок |
| **Ручные процессы (Excel)** | Привычка к ручной работе, низкая скорость | Сложность перехода на автоматизацию |
| **Сопротивление изменениям** | Страх перед новыми инструментами | Затягивание сроков, саботаж |

### 3.6. Процессы

| Проблема | Описание | Влияние на миграцию |
|----------|----------|---------------------|
| **Нет CI/CD** | Ручной деплой, долгие релизы | Невозможность быстрой доставки изменений |
| **Нет автоматических тестов** | Регрессии, нет уверенности в качестве | Риск падений после каждого релиза |
| **Отсутствие Data Governance** | Нет стандартов работы с данными | Хаос в данных, проблемы с качеством |

## 4. Рекомендации по устранению узких мест

### 4.1. Инфраструктура

| Мера | Приоритет | Ожидаемый эффект |
|------|-----------|------------------|
| Миграция на Kubernetes-кластер | 🔴 Критичный | Горизонтальное масштабирование, отказоустойчивость |
| Внедрение сегментации сети (VPC, NSG) | 🟠 Высокий | Безопасность, контроль трафика |
| Переход на распределённое хранилище (MinIO / S3) | 🟠 Высокий | Устранение I/O бутылочного горлышка, репликация |

### 4.2. Программное обеспечение

| Мера | Приоритет | Ожидаемый эффект |
|------|-----------|------------------|
| Переход 1С на клиент-серверный режим или облачную версию | 🔴 Критичный | Устранение блокировок, транзакционность |
| Миграция Excel-данных в PostgreSQL | 🔴 Критичный | ACID, согласованность, скорость |
| Замена Exchange на современный notification-сервис | 🟡 Средний | Безопасность, масштабируемость |

### 4.3. Интеграция

| Мера | Приоритет | Ожидаемый эффект |
|------|-----------|------------------|
| Замена OLE на REST API с mTLS | 🔴 Критичный | Безопасность, асинхронность |
| Разработка API-шлюза (Kong / Spring Cloud Gateway) | 🔴 Критичный | Контроль доступа, rate limiting, маршрутизация |
| Внедрение API-интеграции с лабораторией | 🟠 Высокий | Автоматизация, скорость |

### 4.4. Данные

| Мера | Приоритет | Ожидаемый эффект |
|------|-----------|------------------|
| Внедрение шифрования at rest и in transit | 🔴 Критичный | Соответствие 152-ФЗ |
| Внедрение тегирования и классификации (Apache Atlas) | 🔴 Критичный | ABAC, аудит |
| Разработка политик Retention | 🟠 Высокий | Соответствие законодательству, оптимизация хранения |

### 4.5. Персонал

| Мера | Приоритет | Ожидаемый эффект |
|------|-----------|------------------|
| Найм DevOps-инженера с опытом Kubernetes | 🔴 Критичный | Ускорение миграции |
| Обучение команды (Kubernetes, микросервисы, DDD) | 🟠 Высокий | Повышение компетенций |
| Внедрение Agile / Scrum с вовлечением всей команды | 🟡 Средний | Снижение сопротивления |

### 4.6. Процессы

| Мера | Приоритет | Ожидаемый эффект |
|------|-----------|------------------|
| Внедрение CI/CD (GitLab CI / GitHub Actions) | 🔴 Критичный | Быстрые и безопасные релизы |
| Внедрение автоматического тестирования (unit, integration, e2e) | 🔴 Критичный | Качество, уверенность |
| Создание Data Governance-комитета | 🟠 Высокий | Стандарты, контроль качества данных |

## 5. Приоритеты и дорожная карта

| Этап | Срок | Ключевые меры |
|------|------|---------------|
| **1. Foundation** | 1–2 месяца | Найм DevOps, CI/CD, автоматические тесты, API-шлюз |
| **2. Data Migration** | 2–4 месяца | Шифрование, тегирование, миграция данных в PostgreSQL |
| **3. Integration** | 3–5 месяцев | Замена OLE, API с лабораторией, переход 1С в облако |
| **4. Infrastructure** | 4–6 месяцев | Kubernetes, распределённое хранилище, сегментация сети |
| **5. People & Processes** | Постоянно | Обучение, Agile, Data Governance |

## 6. Заключение

Миграция «Медикаменте» — сложный, но выполнимый проект. Ключевые риски связаны с:

1. **Устаревшими интеграциями** (OLE, файловый 1С) — требуют полной переработки.
2. **Данными** — необходимо обеспечить шифрование и классификацию до миграции.
3. **Персоналом** — требуется усиление команды и обучение.

При системном подходе и соблюдении предложенных рекомендаций миграция завершится успешно в установленные сроки.
