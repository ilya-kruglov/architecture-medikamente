# Task 2: Проектирование решения

## Цель
Разработать целевую архитектуру системы «Медикаменте» (MVP на ближайшие месяцы), которая встраивает принципы Privacy by Design (PbD) на всех уровнях – от сбора данных до их аналитической обработки.

## Ключевые принципы PbD, применённые в решении
1. **Проактивность** – защита данных закладывается на этапе проектирования, а не добавляется позже.
2. **Приватность по умолчанию** – все данные по умолчанию шифруются, доступ минимален.
3. **Встроенная защита** – механизмы безопасности (IAM, шифрование, аудит, тегирование) являются неотъемлемой частью платформы.
4. **Полная функциональность** – безопасность не должна мешать бизнесу; мы достигаем баланса через дифференцированный доступ.
5. **End‑to‑end безопасность** – данные защищены на всём жизненном цикле (сбор, хранение, обработка, передача, удаление).
6. **Прозрачность** – аудит и логирование дают полную видимость операций с данными.
7. **Уважение к приватности** – пользователи получают контроль над своими данными (запросы на удаление, выгрузку).

## Новые блоки архитектуры
На основе анализа As‑Is мы добавляем следующие компоненты:

| Блок | Назначение | Соответствие PbD |
|------|------------|------------------|
| **API Gateway** | Единая точка входа для всех внешних и внутренних запросов; валидация, rate limiting, WAF. | Проактивная защита, контроль входящего трафика. |
| **IAM (Identity & Access Management)** | Аутентификация (с поддержкой MFA), авторизация на основе RBAC/ABAC, интеграция с AD/LDAP. | Приватность по умолчанию – доступ только по необходимости. |
| **Policy Enforcement Point (PEP)** | Централизованное применение политик доступа на основе тегов данных (ABAC). Реализуется через Open Policy Agent (OPA). | Встроенная защита, контроль на уровне данных. |
| **Data Tagging & Metadata Service** | Автоматическое и ручное тегирование данных, управление метаданными, классификация. | Позволяет применять политики дифференцированно. |
| **Encryption & Key Management** | Шифрование at rest и in transit, управление ключами (HashiCorp Vault). | End‑to‑end безопасность. |
| **Audit & Logging Service** | Централизованный сбор логов доступа и операций с данными; интеграция с SIEM. | Прозрачность, возможность расследования. |
| **Anonymization / De‑identification Service** | Обезличивание данных для аналитики (удаление/маскирование ПДн/PII). | Позволяет использовать данные без нарушения приватности. |
| **Data Lake (Analytics)** | Хранилище обезличенных данных для BI, ML и AI-задач. | Разделение операционных и аналитических данных. |

Все эти блоки интегрируются в целевую архитектуру, как показано на диаграммах C4.

## Аналитический слой (Data Lake)
Выделен в отдельный слой, куда данные попадают только после обязательного обезличивания. Это гарантирует, что аналитики, дата-сайентисты и BI-инструменты работают с данными, которые нельзя привязать к конкретному пациенту. Используются методы k‑анонимности, дифференциальной приватности и агрегации.
