# Метрики оценки эффективности классификации данных

## 1. Качество классификации (ML-метрики)

| Метрика | Описание | Целевое значение | Способ измерения |
|---------|----------|------------------|------------------|
| **Precision (Точность)** | Доля правильно классифицированных данных среди всех, отнесённых к классу | > 0.95 | Сравнение с ручной разметкой выборки (1000 записей) |
| **Recall (Полнота)** | Доля правильно классифицированных данных среди всех, которые должны были быть отнесены к классу | > 0.92 | Сравнение с эталонной разметкой |
| **F1-Score** | Гармоническое среднее precision и recall | > 0.93 | Автоматический расчёт |
| **Accuracy** | Общая доля верных классификаций | > 0.97 | Автоматический расчёт |
| **Confusion Matrix** | Матрица ошибок по классам | Минимум ошибок между PII/Medical | Визуализация в Kibana |

## 2. Операционные метрики

| Метрика | Описание | Целевое значение | Способ измерения |
|---------|----------|------------------|------------------|
| **Throughput (пропускная способность)** | Количество записей, обработанных за единицу времени | > 10 000 записей/мин | Prometheus (Count of processed records) |
| **Latency (задержка)** | Время от получения данных до завершения классификации | p95 < 500 мс | Prometheus (Histogram) |
| **Error Rate** | Доля записей, не прошедших классификацию | < 0.1% | Логи ошибок |
| **DLQ Size** | Размер очереди недоставленных сообщений | < 1000 | Мониторинг Kafka |

## 3. Бизнес-метрики

| Метрика | Описание | Целевое значение | Способ измерения |
|---------|----------|------------------|------------------|
| **False Negative Rate (PII пропущены)** | Доля ПДн/PII, не обнаруженных системой | 0% (критично) | Ежедневный аудит выборки |
| **False Positive Rate (ложные срабатывания)** | Доля не-PII, ошибочно отнесённых к PII | < 1% | Сравнение с ручной проверкой |
| **Compliance Score** | Оценка соответствия 152-ФЗ | 100% | Внешний аудит, отчёты DPO |
| **Time to Detect (TTD)** | Время обнаружения ПДн/PII в новых данных | < 1 сек (реальное время) | Мониторинг |

## 4. Метрики для оптимизации

| Метрика | Использование |
|---------|---------------|
| **Model Drift** | Отслеживание изменения precision/recall во времени для переобучения моделей |
| **Feature Importance** | Определение, какие поля чаще всего содержат ПДн/PII → оптимизация сканирования |
| **Resource Utilization (CPU/Memory)** | Оптимизация размера Spark-кластера и количества нод |
| **Data Volume per Classification** | Планирование масштабирования при росте данных |

## 5. Процесс сбора и визуализации метрик

- **Сбор:** Prometheus (PushGateway для Spark-джобов) + Filebeat → Elasticsearch
- **Визуализация:** Grafana (дашборды для инженеров) + Kibana (для аудита и DPO)
- **Алерты:**
  - Precision < 0.90 → Warning
  - Recall < 0.85 → Critical
  - False Negative обнаружена → Critical (эскалация в DPO)
  - Latency p95 > 1 сек → Warning

## 6. Частота переобучения моделей

| Модель | Частота переобучения | Триггер |
|--------|----------------------|---------|
| NER-модель (spaCy) | Ежеквартально | Снижение F1 < 0.90 |
| Regex-паттерны | По запросу | Новые форматы ПДн/PII (изменение законодательства) |
| OCR-модель | Ежеквартально | Улучшение точности распознавания |
| Классификатор (правила) | Ежемесячно | Изменение бизнес-процессов |
