# Аудит мер безопасности и список проблемных зон

## 1. Методология оценки
Аудит проведён на основе:
- Требований 152-ФЗ «О персональных данных»
- Принципов Privacy by Design (PbD)
- NIST SP 800-53 (контроль доступа, аудит, шифрование)
- Лучших практик Data Minimization и Data Lineage

## 2. Сопоставление процессов с требованиями

| Бизнес-процесс | Данные | Текущая мера защиты | Требование | Статус |
|----------------|--------|---------------------|------------|--------|
| Регистрация пациента | ФИО, дата рождения, телефон, email, адрес, место работы, заболевания | Нет | 152-ФЗ ст.19 (защита ПДн) | ❌ Критично |
| Хранение медицинских карт | Сканы паспорта, результаты обследований | Общий доступ | 152-ФЗ ст.6 (обработка ПДн) | ❌ Критично |
| Запись к специалисту | ФИО, телефон, время, специалист | Нет аудита | 152-ФЗ ст.21 (обязанности оператора) | ❌ Высокий |
| Приём оплаты | Данные платежа, ПДн | Двойной учёт в Excel | 152-ФЗ ст.19 | ❌ Высокий |
| Лабораторные исследования | Результаты анализов + ПДн | Нет шифрования | 152-ФЗ ст.19 | ❌ Критично |
| Учёт ТМЦ | Данные о закупках | OLE-интеграция | 152-ФЗ (косвенно) | ⚠️ Средний |
| Уведомления | Email, телефон | Exchange без шифрования | 152-ФЗ ст.19 | ❌ Высокий |

## 3. Детальный список проблемных зон

### 3.1. Хранение данных (Storage)
| # | Проблема | Описание | Риск | Приоритет |
|---|----------|----------|------|-----------|
| S1 | Отсутствие шифрования | Все файлы (Excel, PDF, JPG) хранятся в открытом виде на файловом сервере | Утечка при компрометации сервера | 🔴 Критичный |
| S2 | Отсутствие классификации | Данные не разделены по категориям чувствительности | Невозможно применить дифференцированную защиту | 🟠 Высокий |
| S3 | Бессрочное хранение | Нет политики удаления данных | Нарушение 152-ФЗ (сроки хранения) | 🟠 Высокий |
| S4 | Неструктурированное хранение | Сканы и PDF в папках без метаданных | Невозможность поиска и аудита | 🟡 Средний |

### 3.2. Доступ к данным (Access)
| # | Проблема | Описание | Риск | Приоритет |
|---|----------|----------|------|-----------|
| A1 | Отсутствие RBAC | Все сотрудники имеют доступ ко всем данным | Несанкционированный доступ | 🔴 Критичный |
| A2 | Общий сетевой диск | Данные доступны по LAN без аутентификации | Перехват трафика | 🔴 Критичный |
| A3 | Нет разделения по ролям | Врач видит данные всех пациентов | Нарушение врачебной тайны | 🔴 Критичный |
| A4 | Доступ к 1С без МФА | Только парольная защита | Компрометация учётной записи | 🟠 Высокий |

### 3.3. Передача данных (Transmission)
| # | Проблема | Описание | Риск | Приоритет |
|---|----------|----------|------|-----------|
| T1 | OLE без шифрования | Интеграция 1С ↔ ККМ по TCP/IP без TLS | Перехват платежных данных | 🔴 Критичный |
| T2 | Email без шифрования | Exchange передает уведомления в открытом виде | Перехват ПДн | 🟠 Высокий |
| T3 | Нет API-шлюза | Лаборатория получает данные неконтролируемо | Утечка через внешнего контрагента | 🔴 Критичный |
| T4 | Нет контроля исходящих данных | Данные уходят в лабораторию без аудита | Нарушение 152-ФЗ (передача третьим лицам) | 🔴 Критичный |

### 3.4. Аудит и мониторинг (Audit)
| # | Проблема | Описание | Риск | Приоритет |
|---|----------|----------|------|-----------|
| AU1 | Отсутствие логирования | Не фиксируется кто, когда и что делал с данными | Невозможность расследования инцидентов | 🔴 Критичный |
| AU2 | Нет алертинга | Система не оповещает о подозрительных действиях | Инцидент может остаться незамеченным | 🟠 Высокий |
| AU3 | Нет Data Lineage | Не отслеживается происхождение и трансформация данных | Нарушение требований к прослеживаемости | 🟡 Средний |

### 3.5. Управление идентификацией (IAM)
| # | Проблема | Описание | Риск | Приоритет |
|---|----------|----------|------|-----------|
| I1 | AD без интеграции с приложениями | 1С и файловый сервер используют отдельные учётки | Усложнение управления доступом | 🟠 Высокий |
| I2 | Нет SSO | Пользователи имеют несколько паролей | Слабые пароли, риск компрометации | 🟡 Средний |
| I3 | Нет жизненного цикла доступа | При увольнении доступ не всегда отзывается | Бывшие сотрудники имеют доступ | 🔴 Критичный |

### 3.6. Процессы и политики (Process)
| # | Проблема | Описание | Риск | Приоритет |
|---|----------|----------|------|-----------|
| P1 | Отсутствие DPO | Нет назначенного ответственного за ПДн | Штрафы, репутационные риски | 🟠 Высокий |
| P2 | Нет политики инцидентов | Нет плана реагирования на утечки | Задержка в реагировании | 🟠 Высокий |
| P3 | Нет обучения персонала | Сотрудники не обучены работе с ПДн | Человеческий фактор | 🟡 Средний |

## 5. Вывод
Текущая архитектура не соответствует требованиям 152-ФЗ и представляет **критический риск** для бизнеса. Необходима комплексная трансформация, включающая:
1. Внедрение шифрования на всех уровнях (хранение, передача, использование).
2. Построение RBAC/ABAC на основе классификации данных.
3. Внедрение централизованного аудита и мониторинга.
4. Разработка API-шлюза с контролем доступа.
5. Внедрение Data Lineage и политик управления жизненным циклом данных.
