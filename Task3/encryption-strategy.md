# Стратегия шифрования данных

## 1. Общие принципы
- **Шифрование по умолчанию** – все чувствительные данные шифруются автоматически без необходимости ручной активации.
- **Разделение ключей** – для разных категорий данных используются разные ключи шифрования (изоляция).
- **Централизованное управление ключами** – все ключи хранятся в Vault с строгим контролем доступа и автоматической ротацией.
- **Аудит использования ключей** – каждое обращение к ключу логируется.

## 2. Шифрование At Rest

| Тип хранилища | Метод шифрования | Управление ключами | Дополнительные меры |
|---------------|------------------|--------------------|----------------------|
| Операционная БД (PostgreSQL) | AES‑256‑GCM на уровне таблиц/столбцов (pgcrypto) + TDE (Transparent Data Encryption) на уровне диска | Ключи в Vault, ротация каждые 90 дней | Разделение на схемы по чувствительности |
| Метаданные и теги (PostgreSQL + Elasticsearch) | AES‑256 на уровне диска (LUKS) и на уровне приложения для ПДн/PII | Отдельный ключ | Индексы не должны содержать ПДн/PII в открытом виде |
| Файловое хранилище (сканы, PDF, JPG) | AES‑256‑GCM на уровне файлов (age / GPG) или S3‑совместимое шифрование (SSE‑S3) | Vault для ключей шифрования файлов | Метаданные файлов также шифруются |
| Бэкапы | Шифрование бэкап‑архивов отдельным ключом | Ключ хранится в Vault, не связан с основными | Бэкапы проверяются на целостность |
| Data Lake (ClickHouse/HDFS) | Шифрование данных при записи (AES‑256) и дисковое шифрование | Ключи для каждого топика/таблицы | Применяется для обезличенных данных (опционально) |

## 3. Шифрование In Transit

| Тип соединения | Метод | Управление сертификатами | Дополнительные меры |
|----------------|-------|--------------------------|----------------------|
| Внешние пользователи → API Gateway | TLS 1.3 (HTTPS) | Сертификаты от доверенного ЦС, ротация каждые 90 дней | HSTS, Perfect Forward Secrecy |
| Backend → Backend (внутренние микросервисы) | mTLS (взаимная аутентификация) с сертификатами | Внутренний PKI (Vault) | Service Mesh (Istio) для автоматического mTLS |
| API Gateway → Внешние партнёры (лаборатория) | mTLS + подпись запросов (JWT) | Отдельные сертификаты для каждого партнёра | Rate limiting, белый список IP |
| Backend → 1С (облачная / on‑prem) | TLS 1.3 + OAuth 2.0 (Client Credentials) | Сертификаты или API‑ключи | Шифрование данных на уровне приложения (дополнительное) |
| Пользователи ↔ Mobile App | TLS 1.3, certificate pinning | Сертификаты, pinned в приложении | Защита от Man‑in‑the‑Middle |

## 4. Шифрование In Use (обработка)

| Сценарий | Метод | Обоснование |
|----------|-------|-------------|
| Обработка ПДн/PII в памяти | Использование защищённых анклавов (Intel SGX) или доверенных сред исполнения (TEE) | Для ML/AI-нагрузок, где данные временно расшифрованы |
| Динамическое маскирование | ABAC + OPA – данные маскируются на лету в зависимости от роли | Позволяет работать с данными без раскрытия полного объёма |
| Выгрузка в аналитику | Данные обезличиваются до передачи в Data Lake; в аналитическом слое ПДн/PII не хранятся | Принцип Data Minimization, защита на уровне источника |
| Временные файлы и кеш | Шифрование кеша (Redis) с использованием TLS и опционально шифрования данных на стороне клиента | Кеш может содержать сессии и временные ПДн/PII |

## 5. Управление ключами (Key Management)

- **Хранилище ключей:** HashiCorp Vault (Enterprise или Open Source с HA).
- **Типы ключей:**
  - Master Key (хранится вне системы, используется для распаковки Vault).
  - Ключи шифрования данных (DEK) для каждой категории.
  - Ключи для mTLS и JWT.
- **Политики ротации:** каждые 90 дней для DEK, каждые 180 дней для сертификатов.
- **Аудит:** каждое обращение к Vault логируется, интегрируется с SIEM.
- **Резервирование:** Vault кластеризуется, ключи реплицируются в защищённом виде.

## 6. Пример реализации для PostgreSQL (в коде)

```sql
-- Включение расширения pgcrypto
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- Шифрование столбца при вставке
INSERT INTO patients (id, full_name, phone, encrypted_diagnosis)
VALUES (
  gen_random_uuid(),
  pgp_sym_encrypt('Иванов Иван Иванович', 'key_vault_lookup'),
  pgp_sym_encrypt('+7-999-123-45-67', 'key_vault_lookup'),
  pgp_sym_encrypt('Грипп', 'key_vault_lookup_medical')
);

-- Чтение с расшифровкой (только для авторизованных)
SELECT 
  id,
  pgp_sym_decrypt(full_name, 'key_vault_lookup') AS full_name,
  pgp_sym_decrypt(phone, 'key_vault_lookup') AS phone,
  pgp_sym_decrypt(encrypted_diagnosis, 'key_vault_lookup_medical') AS diagnosis
FROM patients
WHERE id = '...';
```
